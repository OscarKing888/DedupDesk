# DedupDesk

Windows 中文多线程文件去重工具。C# / .NET 10 / WPF / SQLite。为大容量、多磁盘文件库设计，使用有界流水线、持久化完整指纹和分页结果；不会自动删除文件。

## 运行

解压 `DedupDesk-win-x64.zip`，保持包内文件完整，运行 `DedupDesk-win-x64/DedupDesk.exe`。无需安装 .NET。适用于 Windows 10/11 x64；不要求管理员权限。

1. 添加目录，将至少一个设为 **保留目录**，至少一个设为 **待清理目录**。新目录默认保留。双击“用途”单元格可切换角色。
2. 选择比较方式和文件类型，点击“开始扫描”。
3. 在列表中检查重复组，或切换目录树并逐层展开。列表每页 200 条；搜索匹配完整路径。目录树每批加载 200 个子目录。
4. 勾选待清理文件，右键“移入回收站”。也可以右键目录节点，将该节点下已匹配的目标文件逐项回收，不删除目录本身。

只有保留目录存在匹配副本时，目标文件才可回收。保留目录不能被回收。目标目录内部独有的重复组不列为可清理。重叠目录只扫描一次，角色冲突时保留优先。

## 比较方式

| 方式 | 判断规则 | 文件读取 |
|---|---|---|
| 名字＋大小（默认） | 包含扩展名的文件名忽略大小写、字节数相同 | 不读取内容，**未核验内容** |
| MD5 | 字节数和完整 MD5 相同，忽略文件名 | 为所有符合过滤的文件建立完整指纹 |
| SHA-256 | 字节数和完整 SHA-256 相同，忽略文件名 | 为所有符合过滤的文件建立完整指纹 |

哈希模式不使用局部采样作最终判重，不做相似图片、转码视频、音频内容相似识别。MD5 和 SHA-256 有各自的缓存；选择一种算法不会顺便计算另一种。

类型过滤提供全部、照片、视频、照片和视频、自定义扩展名。照片和视频预设在输入框显示并可编辑；合并预设编辑后成为自定义规则。支持 `.jpg; *.png; mp4`，不区分大小写。类型按文件扩展名识别。

## 缓存、并发与恢复

- 默认缓存：`%LocalAppData%\DedupDesk\catalog.db`；设置文件位于同目录的 `settings.json`。可在“设置与缓存”选择其他缓存位置。切换位置使用该位置独立的数据库，不自动搬迁旧缓存。
- 缓存以文件身份、大小、修改时间、创建时间和算法为键。文件身份不可用时按路径回退。修改后重新计算；正常改名可复用稳定身份的缓存。内容改变但保留时间属性可能使扫描缓存过期，所以 **哈希模式回收前始终重新读取目标与保留副本的完整内容**。
- “清理指纹缓存”只清除哈希记录；源文件和扫描结果保持不变。强制重算开关让下一次扫描忽略已有指纹。
- 首次全量哈希需要读完所有符合类型过滤的文件，包括没有重复项的文件。对 20 TB 数据，这通常由存储吞吐量决定，不能通过线程数保证 CPU 满载。
- 默认按磁盘设定读取并发：机械盘 1、SSD 4、NVMe 8、网络路径 2、未知设备 1。系统无法识别 RAID 介质时使用保守值，可手动调整。同一物理磁盘的分区共享读取上限。CPU 计算并发默认逻辑处理器数量。
- 暂停在目录项/文件块边界生效。取消后已完成指纹仍保留。恢复任务重新枚举当前文件并复用缓存；未完成大文件从头计算，不保存哈希中间状态。
- 只保留最近完成扫描的完整结果，避免每次扫描都累积全量文件快照。历次运行配置和回收日志保留，完整指纹跨扫描复用。数据库内删除记录后的空闲页由 SQLite 后续复用。
- 链接目录、符号链接、系统回收站、系统卷信息和自身缓存被跳过。多硬链接文件不作为可释放空间的目标副本。读取/权限错误单独记录，界面最多展示 1000 条，数据库保留该次扫描全部错误。

## 回收保护

- 不存在直接删除、永久删除、清空回收站功能。使用 Windows Shell `IFileOperation`，在专用 STA 线程运行，要求回收并在删除回调中否决非回收操作。系统不支持回收或操作失败时保留原文件并报告错误。
- 第一版仅对本地固定磁盘开放回收；网络目录和可移动设备可扫描，但不执行回收操作。
- 哈希模式回收前绕过持久化缓存重新核验完整内容；保留副本在操作期间保持只读共享句柄，阻止其被写入或删除。目标变化、保留副本缺失、链接或角色变化均拒绝处理。
- 名字＋大小模式遵循用户选择，只重新核验名称、大小、身份与时间属性，**不保证内容相同**。
- 被跳过的回收项需重新扫描后再尝试；回收日志可以在错误记录中查看。成功回收后，可用系统回收站恢复。
- 文件进入回收站后仍可能占用磁盘空间，显示的大小不是立即释放空间。

## 源码与构建

源码在 `src/DedupDesk.Core`（索引、扫描、缓存、回收）及 `src/DedupDesk.App`（WPF 界面）；`tests/DedupDesk.Tests` 是无需额外测试框架的可执行验收套件。没有云服务或遥测代码。

使用 PowerShell：

```powershell
.\build.ps1                                  # 编译并运行隔离测试
.\build.ps1 -Publish                         # 同时生成含运行时的便携包
.\build.ps1 -Publish -Benchmark -RecycleTest # 增加百万条索引基准和真实回收/恢复测试
```

构建脚本将固定版本 .NET 10 SDK 下载到项目 `.tools`，不修改系统 SDK。需要联网下载 SDK 和 NuGet 依赖。输出位于 `artifacts/DedupDesk-win-x64` 与对应 ZIP。

测试只创建并操作 `TestResults` 下唯一命名的隔离数据，不扫描个人目录。`-RecycleTest` 仅回收一个唯一命名的测试文件并自动恢复。测试数据和报告保留在 `TestResults`，便于审查。`-Benchmark` 使用百万条合成索引及 256 MiB 文件数据，不代表真实 20 TB 冷盘性能。

UI 冒烟验证：`DedupDesk.exe --smoke <独立输出目录>`，自动生成隔离数据、扫描并保存列表/树形截图后退出，不执行回收。
